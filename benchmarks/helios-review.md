# Helios 第一轮：基线、对照与修订

日期：2026-11-05。这是第一篇实测，不代表三篇实验或 skill 迁移验证已经完成。

## 产物

本地忽略目录 `outputs/benchmarks/helios/`：

- `baseline/`：冻结的首版 HTML/CSS/JS。
- `revised/`：第一轮修改后的页面。
- `assets/`：7 段作者视频，原始字节未改；逐文件来源、哈希、时长和分辨率在 `media.json`。
- `review/`：桌面/手机首屏、方法部分截图。
- `original-snapshot/`：原站 HTML 的本地排版快照及说明，仅用于本地研究。
- `fault-test/`：故意缺失一个视频的故障样例，不是交付页面。

首版依据 [论文简报](helios-brief.md) 和已冻结的 skill 制作。曾经浏览过原站且读取其素材清单，因此不称作盲测；没有复用作者页面的布局代码。

## 原站比较的边界

本轮原站在检查浏览器中打开后持续超时。原始 HTML、样式、图片和字体可通过 HTTP 正常取得，故本地保留原布局与脚本，并把样式/字体 URL 指向下载副本；CSP 阻止远程嵌入。截图中的 YouTube 空白或缺失视频不能当作原站的加载缺陷。本轮对照支持排版观察，不支持原站完整播放或网络性能结论。

在 1440×900 视口（内容宽 1425）观察，原站标志、居中大标题、全作者与机构、五个资源按钮形成很强的项目身份；首个主功能嵌入框位于约 y=853。新页更早呈现一段大视频，但品牌图形的独特性和任务覆盖广度不及原站。不能用“看见视频更早”宣称整体审美全面更优。

在 390×844 视口（内容宽 375）观察，原站快照第一嵌入框约 y=1107；作者机构信息占据较多纵向空间。原站快照出现横向溢出，但仅记录为该快照的观察，不外推到所有设备/在线状态。

## 基线暴露的问题与修订

| 观察 | 修订 | 已取得证据 |
| --- | --- | --- |
| 桌面左右分栏直接堆叠到手机，作者与资源挤在视频前 | 手机改为身份/主要资源 → 视频 → 完整作者；桌面仍保留作者和媒体并排 | 相同手机视口，视频 top 从 659.86 px 降至 396.71 px；无整页横向溢出 |
| 方法标签在大视频下方，初次看到播放器时难以识别方法 | 对比标签移到视频前 | 修订页 DOM 顺序与渲染检查 |
| 一分钟结果只有连续时间轴，后段不容易快速到达 | 增加 0/20/40/59 秒共同检查点 | 两播放器实际 `currentTime=40`，均 paused，readyState=4 |
| 生成 FPS 与视频文件 FPS 容易混淆 | 分开标注 19.53 generation FPS 与 24 fps playback，并注明模型变体未知 | PDF 第 15–16 页与媒体探测交叉核对 |
| 同 prompt 容易被误写成所有设置相同 | 明示两种源分辨率及未知 seed/逐片采样配置 | 640×384 与 832×480 原文件探测结果 |

前三条带来页面结构和交互变化；后两条是读论文与查媒体后的证据约束。已写回 skill 相关参考文件，下一篇必须检查这些指导是否有效，不能把 Helios 的配色和具体布局写成统一模板。

## 行为验证

实际浏览器检查已通过：

- 初始 5 个 video 均无 src、readyState=0；展示 poster，不提前载入整个目录。
- 主视频真实播放：currentTime 从 0.21 增至 6.14；导航到对比后自动暂停在约 6.26。
- 两个比较视频实际同时播放；未声称逐帧同步。
- 40 秒共同检查点定位成功，保持暂停；之后组播放可以继续。
- 公共结束点两者都停在 60.375 秒，按钮复位且显示完成状态。
- 快速切换 Desert → Tokyo → Desert → Tokyo 后只剩当前 prompt3 的两播放器，未加载且暂停，展开的提示词是 Tokyo 文本。
- 故障样例一个 URL 返回 404 时出现重试/原视频入口；组内另一条视频仍可单独播放。
- 正常修订页面检查时无控制台 error；故障样例的预期 404 单独处理。
- JavaScript 语法检查通过；桌面首屏、手机首屏、桌面方法图已视觉检查。

尚未覆盖：慢网限速、多个同时存在的比较组、浏览器多种 codec、不同实际片长组、所有键盘路径及所有主体片段完整观看。当前播放器不实现时钟漂移校正。不能把此页的检查当作一个通用播放器库的完整验收。
