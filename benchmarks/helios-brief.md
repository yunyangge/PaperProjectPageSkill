## 内容与证据

- 身份：Helios: Real Real-Time Long Video Generation Model；Shenghai Yuan、Yuanyang Yin、Zongjian Li、Xinwei Huang、Xiao Yang、Li Yuan，顺序及单位/标记依第 1 页。
- 访客首先应看到：一段完整的分钟级生成结果；“14B 模型 + 单张 H100 + 19.53 FPS”是推理吞吐量而非视频播放帧率。后者文件实测 24 FPS。
- 第 3 页 Fig.3：鱼、SUV、老人三组长时序展示。选鱼作为开场，观看对象是持续运动、场景及外观随时间的变化；不能凭选定片段宣称不存在漂移。
- 第 5–12 页：历史条件注入统一 T2V/I2V/V2V；相对 RoPE、首帧锚定与历史扰动针对位置、颜色、恢复漂移；多尺度历史压缩、金字塔采样、三步蒸馏降低开销。网页只用三段短解释，保留实际 Fig.4。
- 第 15–16 页：吞吐量测试包含 VAE 和文本编码器，384×640、单 H100、各模型默认帧长及官方加速。Helios-Base/Mid/Distilled 为 0.54/1.05/19.53 FPS。不能把 Base 的展示或质量默认归到 Distilled。
- 第 19 页有文本/表格矛盾：正文总分 7.08、Naturalness 6；Table 4 的 Distilled 行为 6.94、5。暂不抽取这些值作醒目卖点，不自行“修正”论文。
- 第 20–26、30 页：消融涉及历史条件、锚帧、扰动、蒸馏和后训练；用来解释“为什么可以长”，不在首屏逐项罗列。
- 第 27–29 页：T2V、I2V、交互提示词序列。当前试验首版聚焦 T2V 与长视频方法对比；没有把未实现的 I2V/交互播放器写成页面功能。
- 第 31 页：接缝可能闪烁；实验只到 384×640；没有专门设计长视频记忆。作为证据段落的明确限制。
- 第 39 页：评分离散化和加权；不可把质量分与吞吐量混成不带定义的“提升百分比”。

## 方向选择（实验自主选择）

1. 深色放映：紧凑左侧身份与右侧大视频，暖橙强调，媒体主导；适合长视频和推理速度的主线。本轮选用。
2. 浅色画廊：按能力分区，适合更多任务，但当前三条主线容易被均匀网格稀释。
3. 图文叙事：沿“漂移 → 历史 → 压缩”解释，适合方法读者，需避免解释挤占第一段视频。

## 素材与对比

作者项目页 3 条 T2V 展示 + 2 个提示词 × 2 种方法。完整提示词从原 HTML 提取，媒体 SHA256、时长/分辨率/FPS 与 URL 写入本地 media.json。下载总约 52.5 MB，全部仅保存在忽略目录。

- 鱼：60.38 s；博物馆、车窗：各 30.21 s；均 640×384、24 FPS。原站未在这些展示旁注明模型变体，页面保留该未知。
- 比较组：Desert explorer / Tokyo street；Helios 和 Rolling Forcing 均 60.38 s、24 FPS，分别 640×384 和 832×480。原站配对同一 prompt；相同 seed/逐方法采样设置未核实。不得叫成完全匹配设置的受控实验。
- 播放策略：默认无视频请求；点击后加载；组内联动播放/暂停/重播/时间轴；以公共结束点停止，不独立循环；不宣称逐帧同步。
